# S0 双平台算力资源登记与使用边界

## 1. 目的

本文档登记天数 BI-V150 与沐曦曦云 C500（64 GB）的申请、审批、使用、
证据留存和释放状态。这里只提交非敏感摘要；账号、Token、Cookie、SSH 私钥、
公网地址、算力券和个人申请材料不得进入仓库。

状态枚举：

```text
PLANNED → REQUESTED → APPROVED → ACTIVE → RELEASED
                  ↘ REJECTED
                  ↘ EXPIRED
```

没有可核验审批证据时，状态必须保持 `PLANNED` 或 `REQUESTED`，不得写成
`APPROVED`/`ACTIVE`。

### 3.3 数据和证据边界

- 模型权重、数据集和大型原始日志保留在平台或获批存储中，不提交 Git。
- Git 只保存去敏摘要、实验编号、受控对象 ID、相对证据引用和 SHA256。
- 不在命令、Markdown、截图、Issue 或 PR 中写入 Token、Cookie、密码、
  SSH 私钥、真实公网地址或带鉴权参数的 URL。
- 环境变量只按白名单采集；禁止把完整 `env`/`printenv` 输出提交仓库。
- 对外共享、下载模型/数据、延长保留期限或增加成员，必须重新取得审批。
- 平台要求清理时，按其规定删除临时数据并登记完成时间和责任人。

## 6. 释放与清理检查

- [ ] 正式实验结果已关联唯一实验编号和 ENV-ID。
- [ ] 需要保留的原始证据已转移到获批位置并登记 SHA256。
- [ ] 临时模型副本、数据、日志、缓存和 profiler trace 已按平台规则处理。
- [ ] 临时 Token/会话已由资源持有人在受控系统中撤销或到期。
- [ ] 资源状态已更新为 `RELEASED` 或 `EXPIRED`。
- [ ] 释放时间、执行人和复核人已登记。

## 7. S1 启动门禁

只有同时满足以下条件，相关平台才能开始正式 S1 测量：

1. 资源状态为 `APPROVED` 或 `ACTIVE`，且审批证据可由负责人核验；
2. 当前时间位于批准的使用时间窗和配额内；
3. 对应 `ENV-ID` 的必填环境字段已经实测并复核；
4. 模型和数据可访问，凭据未进入仓库；
5. 原始结果、日志和清理位置已经确定；
6. 资源变化、失败和中断均有登记方式。
