## 3. 必须人工检查的内容

`.gitignore` 不能阻止已经被 Git 跟踪的文件，也不能识别所有自定义文件名。每次提交前仍须检查：

- GitHub、Gitee、算力平台 Token；
- SSH 私钥、登录地址、用户名、密码和 Cookie；
- 个人简历、学号、手机号、证件和申请 PDF；
- MiniCPM5-2B 权重与 EvalScope 数据集；
- 完整服务日志、Profiler trace、Core dump 和重复 Benchmark 输出；
- 截图中可能出现的 SSH 地址、平台实例凭据或个人信息。

## 4. 提交前检查命令

```bash
git status --short
git diff --cached --name-only
git diff --cached --check
git ls-files | grep -E '(^|/)(models|datasets|benchmark_results|profiler_traces)/' || true
git grep -n -I -E '(BEGIN (RSA|OPENSSH|EC) PRIVATE KEY|ghp_|github_pat_|api[_-]?key|access[_-]?token|password)' -- . ':!docs/evidence/phase-0/chen-governance/.gitignore-audit.md' || true
```

若命令命中，不代表一定泄密，但必须逐项人工确认后才能 Push。

## 5. 发现敏感文件时

### 尚未提交

```bash
git restore --staged <file>
```

将文件移动到仓库外或补充精确 `.gitignore` 规则，再重新检查。

### 已提交但尚未 Push

停止操作并联系项目负责人；确认文件范围后修正提交。禁止使用覆盖范围不明的破坏性命令。

### 已经 Push 到公开仓库

1. 立即撤销或轮换泄露的 Token/密码；
2. 通知全体成员停止基于该凭据操作；
3. 精确确认受影响提交和文件；
4. 再决定是否需要清理历史，并记录处理过程。

仅删除最新文件不能使历史中的秘密失效，轮换凭据优先于清理历史。

## 6. 审计结论

- 当前 `.gitignore` 已覆盖比赛项目的主要本地产物；
- 仓库是公开仓库，必须保持提交前人工检查；
- `flagos-2026-s2` 当前未启用 GitHub Branch Protection，因此安全依赖团队 PR/Review 规则执行；
- `upstream` 的本地 Push 地址设置为 `no_push`，可降低误推官方仓库的风险；
- 本阶段不将模型、数据集、密钥、个人材料或大型原始结果加入 Git 跟踪。
